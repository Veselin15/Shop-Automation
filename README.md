# shopbot

Автоматизация за препродажба: намира силно намалени артикули в **BestSecret**,
публикува ги като обяви в **Bazar.bg** със снимки и описание, следи ги и ги
сваля, когато продуктът изчезне или спре да бъде намален.

## Стратегията, за която е настроен

| | |
|---|---|
| **Категории** | само аксесоари без размерен риск: слънчеви очила, часовници, портфейли, дамски чанти, мъжки crossbody чантички, ключодържатели, шапки, шалове |
| **Намаление** | минимум 70%, приоритет на 80%+ |
| **Марки** | Guess, Calvin Klein, Tommy Hilfiger, Carrera, Jimmy Choo, Furla, Michael Kors, Emporio Armani, Hugo Boss, Diesel — плюс още ~70 разпознаваеми марки с малко по-нисък приоритет, събрани от обхождане на живо |
| **Цена в BestSecret** | 30–200 € (под това не си струва заявката, над това купувачът не плаща предварително) |
| **Продажба** | по предварителна заявка, ~10 работни дни до офис на куриер — записано е в описанието на всяка обява |

Непознатите марки не са забранени, но минават само при много голямо
намаление (~88%+) или ясен сигнал за търсене. Ето как се държи подборът:

| марка | 70% | 75% | 80% | 88% |
|---|---|---|---|---|
| Guess, Michael Kors, Armani… | ✅ | ✅ | ✅ | ✅ |
| Tissot, Lacoste, Fossil… | ❌ | ✅ | ✅ | ✅ |
| Kipling, Replay, Superdry… | ❌ | ❌ | ✅ | ✅ |
| непозната марка | ❌ | ❌ | ❌ | ✅ |

Регулира се с `selection.popularity.min_score`. Този скор обаче мери само
сигнали ОКОЛО продукта и не вижда самия артикул, затова е нагласен ниско и
служи за груб филтър.

Истинската преценка я прави **оценката от модел** (`appraisal` в конфига):
снимката и името отиват при модел, който казва колко е вероятно българин да
купи точно този артикул на точно тази цена. Така отпадат екстравагантните
форми, намалени с 80% именно защото никой не ги е поискал. Прагът е по
категории — часовник с добра марка се продава и когато е скучен, а очилата
се търсят само ако формата е носима.

Доставчикът се сменя с `appraisal.provider`:

| provider | цена | какво иска |
|---|---|---|
| `gemini` (по подразбиране) | безплатен таван | `GEMINI_API_KEY` от aistudio.google.com, без карта |
| `ollama` | нула | инсталиран ollama на сървъра и визуален модел (`ollama pull llava`) |
| `anthropic` | платено | `ANTHROPIC_API_KEY` |

Проба върху един продукт:

```bash
./shopbot inspect <адрес-от-bestsecret> --category watches_men
```

## Какво прави, стъпка по стъпка

```
BestSecret                        база (SQLite)                    Bazar.bg
─────────────────                 ─────────────                    ─────────
обхожда категории  ──► подбор ──► кандидат ──► ценообразуване ──►  публикува
                       (скор)                    (надценка)         обявата
                                       │
повторна проверка  ──► изчезнал? ──────┘                       ──►  сваля
на всеки ~90 мин       изчерпан?                                    обявата
                       поскъпнал?
```

1. **Откриване** — обхожда категориите от `config/config.yaml`, събира продуктите
   заедно със сигналите от листинга (позиция, bestseller етикет).
2. **Подбор** — твърди филтри (намаление, цена, брой налични размери, марка),
   после скор за популярност. Минава само това, което е над прага.
2а. **Оценка от модел** — снимката отива при модела, който преценява има ли
   артикулът реален шанс да се купи. Оценката се пази в базата и не се плаща
   втори път за същия продукт.
3. **Ценообразуване** — надценка върху цената в BestSecret плюс буфер за
   доставка, с гарантиран минимален марж и закръгляне до `.90`.
4. **Текст на обявата** — заглавие, което започва с „Чисто нов" в правилния род,
   и описание с истинските характеристики от продуктовата страница, преведени
   на български. Непознато поле отпада — нищо не се съчинява.
5. **Публикуване** — попълва формата на Bazar.bg като човек, качва снимките.
   Между две обяви чака 3–5 минути. Всяка категория получава дял от обявите
   според `weight` (часовниците — най-голям). Опашката помни какво е излязло
   през последния ден, за да не гладуват очилата и шапките; вътре в
   категорията първо излизат най-високо оценените.
6. **Следене** — на всеки цикъл проверява публикуваните продукти и сваля
   обявите на тези, които вече не стават: изчезнал, изчерпан или намалението
   е паднало осезаемо спрямо деня на публикуване.
7. **Място в профила** — Bazar.bg пуска до 100 обяви на профил и брои и
   деактивираните. При всяко влизане ботът чете „Моите обяви“: колко места са
   заети и какви прегледи, показани телефони и добавяния в любими има всяка
   обява. Свалените обяви се трият, а не се деактивират. Когато местата
   свършат, обява на поне 5 дни с малко прегледи, без показан телефон и без
   любими отстъпва мястото си на кандидат с ясно по-висока оценка. Дялът по
   категории се пази и тук. Какво би се сменило сега: `shopbot rotation`.

## Инсталация

### На домашния сървър (Ubuntu)

```bash
git clone <твоето repo> ~/Shop-Automation && cd ~/Shop-Automation && bash deploy/install.sh
```

Скриптът вдига venv, тегли Chromium за Playwright и слага systemd услуга.

### Локално (Windows, за настройка и тестове)

```powershell
py -3.12 -m venv .venv ; .\.venv\Scripts\pip install -e . ; .\.venv\Scripts\playwright install chromium
```

За кирилица в конзолата на Windows: `$env:PYTHONIOENCODING = "utf-8"`.

### Как се пускат командите

`shopbot` живее вътре във venv-а, не в системния PATH, а всяка нова SSH сесия
започва без активиран venv. Затова в корена на проекта има обвивка, която
работи винаги:

```bash
./shopbot status
```

```powershell
.\shopbot.ps1 status
```

Обвивката вика двоичния файл от venv-а по абсолютен път — върши работа и от
скриптове, и от cron, и веднага след `git pull`.

Ако предпочиташ да пишеш само `shopbot`, активирай venv-а веднъж на сесия:

```bash
source .venv/bin/activate
```

```powershell
.\.venv\Scripts\Activate.ps1
```

Командите по-долу са писани като `shopbot ...`; сложи `./` отпред, ако не си
активирал venv. Пускат се от корена на проекта, не от `src/`.

Ако обвивката се оплаче, че липсва двоичният файл, проектът не е инсталиран:

```bash
./.venv/bin/pip install -e .
```

## Първоначална настройка (по този ред)

### 1. `.env`

```
TELEGRAM_BOT_TOKEN=...     # по избор, но искаш да знаеш кога нещо се счупи
TELEGRAM_CHAT_ID=...

BAZAR_EMAIL=...            # нужни само ако изключиш двуфакторната
BAZAR_PASSWORD=...
```

Пароли за BestSecret не се пазят изобщо — входът там е ръчен. За Bazar.bg
също, докато двуфакторната аутентикация е включена (виж стъпка 2).

**Telegram (по избор, но искаш го).** Оттам разбираш, че сесията е паднала или
че обява не е минала, без да гледаш логове.

1. В Telegram пиши на **@BotFather**, пусни `/newbot`.
2. Дай име (каквото и да е) и потребителско име, което **свършва на `bot`** —
   напр. `veski_shopbot`.
3. BotFather връща токен от вида `8123456789:AA...`. Сложи го в
   `TELEGRAM_BOT_TOKEN`.
4. Отвори своя бот (`https://t.me/<потребителското име>`) и натисни **Start**.
   Без тази стъпка Telegram не показва разговора и няма как да се вземе id-то.
5. Пусни `shopbot test-notify` — показва намерените разговори и id-тата им.
   Сложи своето в `TELEGRAM_CHAT_ID` и пусни командата пак; трябва да получиш
   пробно съобщение.

За известия в група: добави бота в групата, напиши нещо и пусни `test-notify`
пак — id-то на групата започва с `-100`.

### 2. Ръчен вход в BestSecret

BestSecret е зад покана и не пуска автоматичен вход. Влизаш веднъж с видим
браузър, сесията остава на диска в `data/profiles/bestsecret`:

```bash
shopbot login bestsecret
```

Сървърът няма екран, затова входът се прави на компютъра ти и сесията се
пренася. **Не копирай папката с профила** — Chromium криптира бисквитките с
ключ на операционната система (DPAPI под Windows) и профил от Windows не се
чете от Linux.

`shopbot login` **сам изнася** сесията в `data/sessions/bestsecret.json`, още
докато браузърът е отворен. Това не е дреболия: входът в BestSecret е
*session cookie* — без срок на валидност, тя живее само в паметта на браузъра
и изчезва при затварянето му. Затова отделен `export-session` след това би
хванал само трайните бисквитки (език, държава) и сесията би изглеждала празна.

```bash
scp data/sessions/bestsecret.json veski4a@192.168.0.101:~/Shop-Automation/
```

```bash
./.venv/bin/shopbot import-session bestsecret --file ~/Shop-Automation/bestsecret.json
```

`import-session` веднага проверява дали сесията работи и казва, ако не.

Ботът влива този JSON в профила преди всеки цикъл, но само бисквитките, които
профилът няма или държи с по-ранен срок. Входът в Bazar.bg е `jwt` за 24
минути плюс трайна `pl` за 3 месеца, която сайтът сменя при всяко подновяване
на `jwt` — старата `pl` от файла, наляна отгоре, изхвърляше бота на втория
цикъл след всеки внос. Затова след всеки цикъл с успешен вход ботът записва
живата сесия обратно в същия JSON — файлът не остарява, а при следващия старт
влива днешните `jwt` и `pl`. При стена не записва нищо, за да не затрие добрия
файл. Сесията все пак изтича след време; тогава получаваш 🔐 в Telegram и
повтаряш `login` + пренасяне.

Ако все пак имаш X сървър на Windows (VcXsrv, MobaXterm), можеш и направо:
`ssh -X veski4a@192.168.0.101` и `./.venv/bin/shopbot login bestsecret`.

**Bazar.bg е по същия начин.** Профилът има включена двуфакторна
аутентикация, така че автоматичен вход с парола не може да мине — API-то
връща `requires_2fa` и всеки опит само поръчва нов код. Затова
`bazar.password_login` в конфига е `false` и сесията се прави ръчно:

```bash
shopbot login bazar
```

Въвеждаш имейл, парола и кода, натискаш Enter в конзолата — сесията се
изнася автоматично. После същото пренасяне:

```bash
scp data/sessions/bazar.json veski4a@192.168.0.101:~/Shop-Automation/
```

```bash
./.venv/bin/shopbot import-session bazar --file ~/Shop-Automation/bazar.json
```

Ако някога изключиш двуфакторната, върни `password_login: true` и ботът ще
влиза сам с данните от `.env`.

### 3. Категориите в BestSecret — вече попълнени

`config/config.yaml` идва с проверени адреси за дванадесет категории (дамски
и мъжки: очила, часовници, чанти, портфейли/дребни аксесоари, шапки, шалове).
Взети са от логнат профил, не по памет. Схемата на сайта е:

```
/category.htm?area=WOMEN_ACCESSORIES&category=women_accessoires_sonnenbrillen
```

Не е нужно да пипаш нищо. Ако все пак искаш да стесниш обхвата, приложи
филтрите в самия BestSecret и замени `url` с адреса от адресната лента —
ботът слива query параметрите правилно и страницирането не чупи филтрите.

**Подборът не зависи от филтрите на сайта.** Плочката в листинга носи марка,
каталожна цена, процент намаление и цена, така че ботът отсява там и отваря
продуктова страница само за оцелелите — от 124 плочки към ~20 отваряния.

### 4. Проверка преди първата обява

Селекторите и за двата сайта са проверени на живо и работят — не остава
ръчно калибриране. Виж какво би качил, без да пипаш Bazar.bg:

```bash
shopbot once --no-publish -v
```

```bash
shopbot candidates
```

Показва марка, заглавие, намаление, цена и марж за всичко в опашката.
За един конкретен продукт:

```bash
shopbot inspect "<адрес на продукт в BestSecret>" --category sunglasses_women
```

Ако някой ден сайт смени дизайна си, `shopbot calibrate bazar` (или
`bestsecret`) изкарва структурата на страницата в `data/`, за да обновиш
`config/selectors.yaml`. Всяко поле там е списък от кандидати — ботът пробва
отгоре надолу, така че старите стойности могат да останат.

### 5. Пробно попълване без изпращане

```bash
shopbot once --dry-run -v
```

Попълва формата в Bazar.bg и спира преди бутона, като записва
`data/dry_run_form.png`. Погледни снимката — там се виждат сгрешени полета.

### 6. Пускане

```bash
sudo systemctl enable --now shopbot
journalctl -u shopbot -f
```

## Команди

| Команда | За какво е |
|---|---|
| `shopbot login <bestsecret\|bazar>` | ръчен вход с видим браузър, записва сесията |
| `shopbot export-session <site>` | изнася сесията като преносим JSON |
| `shopbot import-session <site> --file X` | внася сесия на друга машина и я проверява |
| `shopbot once [--dry-run]` | един пълен цикъл |
| `shopbot run` | непрекъснат режим (това пуска systemd) |
| `shopbot status` | какво има в базата, брой публикувани днес, последни събития |
| `shopbot candidates` | какво чака публикуване, с марж |
| `shopbot listings` | активните обяви, продуктите зад тях, прегледи/телефон/любими |
| `shopbot rotation` | коя обява би отстъпила място на кой кандидат при пълен профил |
| `shopbot inspect <url>` | решението за един продукт: минава ли, на каква цена |
| `shopbot calibrate <site>` | изкарва структурата на страницата за `selectors.yaml` |
| `shopbot sync` | сверява базата с реално активните обяви в Bazar.bg |
| `shopbot remove <id>` | сваля една обява веднага и я отбелязва в базата |
| `shopbot models` | кои Gemini модели приема ключът от `.env` |
| `shopbot test-notify` | проверява Telegram токена и намира chat id-то |

`shopbot sync` е важна, ако си трил обяви ръчно — иначе продуктът остава
записан като публикуван и никога не се пуска отново.

## Настройки, които ще пипаш най-често

Всичко е в `config/config.yaml` и се чете при всеки цикъл — без рестарт.

```yaml
selection:
  min_discount_pct: 70        # твърд праг, втора защита след филтъра в BestSecret
  min_source_price: 30.0      # под това печалбата не оправдава заявката
  max_source_price: 200.0     # над това купувачът не плаща предварително
  popularity:
    min_score: 0.30           # груб предфилтър; истинската преценка е appraisal
    unknown_brand_tier: 0.35  # свали го, за да отсееш още непознати марки
    brand_tiers:
      "Guess": 1.0            # частично съвпадение: "Armani" хваща и "Emporio Armani"

appraisal:                     # моделът гледа снимката и казва ще се купи ли
  provider: gemini             # безплатен таван; или ollama (локално), anthropic
  min_score: 0.55
  min_score_by_category:
    watches_men: 0.45          # добрата марка се продава и когато е скучна
    sunglasses_men: 0.70       # тук формата решава

pricing:
  default_markup: 1.30           # +30% върху цената в BestSecret
  markup_by_category:
    bags_women: 1.25             # при чантите процентът се набива в очите
    small_accessories_women: 1.45  # при дребните е малко пари
  shipping_buffer: 4.50          # доставката от BestSecret до теб
  min_absolute_margin: 12.0      # заявка + 10 дни чакане си имат цена

limits:
  max_publish_per_day: 25     # най-важната настройка за безопасност
  max_product_pages_per_run: 120  # дели се между категориите по `weight`
  profile_slots: 100          # таванът на Bazar.bg — броят се и неактивните

rotation:                     # пълен профил: слабата обява отстъпва място
  min_age_days: 5             # по-млада обява още не е показала нищо
  margin: 0.05                # с колко кандидатът бие обявата, която сменя
  max_per_day: 10

runtime:
  min_publish_delay_s: 180    # 3-5 минути между две обяви; серия обяви
  max_publish_delay_s: 300    # една след друга вика проверка „не сте робот"

removal:
  mode: delete                    # деактивираната обява пак заема място от стоте
  remove_below_discount_pct: 60   # твърд под, каквото и да е било преди
  max_discount_drop_pct: 5        # 75% -> 72% остава, 75% -> 65% пада
  misses_before_removal: 2        # две поредни липси, не една

listing:
  delivery_note: |                # влиза в описанието на всяка обява
    Артикулът се доставя по предварителна заявка.
    Срокът за доставка до офис на куриер е около 10 работни дни.
```

Каква цена излиза на практика (при 80% намаление):

| категория | BestSecret | обява | твой марж | каталог |
|---|---:|---:|---:|---:|
| ключодържател | 30 € | 58.90 € | 24.40 € | 150 € |
| портфейл | 45 € | 79.90 € | 30.40 € | 225 € |
| слънчеви очила | 60 € | 100.90 € | 36.40 € | 300 € |
| дамска чанта | 120 € | 180.90 € | 56.40 € | 600 € |
| мъжки часовник | 190 € | 272.90 € | 78.40 € | 950 € |

Маржът е преди твоите разходи за куриер и време. Условията за плащане
(капаро, наложен платеж) не са заложени никъде — реши ги сам и ги допиши в
`listing.extra_note`.

**Валута.** По подразбиране обявите са в EUR. Ако при теб Bazar.bg още работи
в лева, смени `pricing.output_currency: BGN` — всички сметки се преизчисляват
по фиксирания курс.

## Как решава кое е „популярно"

Скор от 0 до 1, претеглена сума от пет сигнала (тежестите са в конфига):

| Сигнал | Тегло | Откъде идва |
|---|---|---|
| ниво на марката | 0.40 | твоят списък в `brand_tiers` |
| размер на намалението | 0.25 | цена спрямо каталожна, мери се над прага от 70% |
| bestseller етикет | 0.15 | етикет в листинга |
| малка наличност | 0.10 | „остават N бройки" на продуктовата страница |
| позиция в листинга | 0.10 | колкото по-напред, толкова по-търсено |

Марката тежи най-много — това е причината топ марка да мине още при 70%, а
непозната да ѝ трябват 88%. Марка извън списъка получава `unknown_brand_tier`
(0.35): не отпада, но трябва да компенсира.

**Този скор обаче не вижда самия артикул** и точно там греши: очила с
екстравагантна форма минават заради марката и намалението, а скучен часовник
от позната марка пада. Затова прагът му е нисък (0.30) и служи за груб
предфилтър, а решението „ще се купи ли" го взима оценката от модел.

Съвпадението по марка е частично и без разлика в главни/малки букви, защото
BestSecret изписва имената по няколко начина — `"Armani": 1.0` в конфига хваща
и „Emporio Armani", и „Giorgio Armani"; `"Guess"` хваща и „GUESS Accessories".

## Безопасност на профилите

Това е автоматизация върху два сайта, които не я предвиждат. Заложено е:

- **Дневни тавани** — 8 публикации и 25 сваляния на ден по подразбиране.
- **Работен прозорец** — 09:00–22:30. Обява в 3 сутринта личи.
- **Паузи** — 20–75 секунди между действията, пишене със забавяне.
- **Honeypot** — формата за вход на Bazar.bg има скрито поле `contact_website`.
  Ботът умишлено не го докосва; попълването му издава автоматизация.
- **CAPTCHA не се заобикаля.** Изникне ли login wall или проверка, ботът спира
  за този сайт, праща известие в Telegram и чака ти да влезеш ръчно.
- **Източникът не се споменава** в обявите — думите „BestSecret" и подобни се
  изчистват от заглавието и описанието.

Въпреки това: условията на BestSecret забраняват препродажба и автоматизиран
достъп, а Bazar.bg може да ограничи профил с много еднотипни обяви. Рискът е
блокиран акаунт и той е реален. Затова лимитите по подразбиране са ниски —
вдигай ги бавно и гледай какво става.

## Работа на сървъра

Всички команди са в `~/Shop-Automation`, през venv-а: `./.venv/bin/shopbot ...`

**Командите, които пипат Bazar.bg, се пускат през `xvfb-run`:**

```bash
SHOPBOT_HEADLESS=0 xvfb-run -a shopbot calibrate bazar
```

В headless режим Chromium се представя като `HeadlessChrome` в User-Agent и
част от сайтовете отказват вход без никакво съобщение. Xvfb дава виртуален
екран, така че върви истински браузър — без да се фалшифицира нищо.
systemd услугата вече е настроена така.

```bash
sudo systemctl status shopbot        # работи ли
sudo systemctl restart shopbot       # рестарт
sudo systemctl stop shopbot          # спиране
journalctl -u shopbot -f             # логът на живо
journalctl -u shopbot --since today  # днешният лог
```

Услугата има `Restart=on-failure` с 60 секунди изчакване, така че сама се
вдига след срив или рестарт на машината.

### Обновяване на бота

```bash
cd ~/Shop-Automation
git pull
./.venv/bin/pip install -e .          # само ако pyproject.toml се е променил
sudo systemctl restart shopbot
```

`config/config.yaml` се чете при всеки цикъл, така че промяна в праговете,
марките или цените **не иска рестарт** — само `git pull` (или редакция на
място). Рестарт трябва само при промяна в кода.

Внимание при `git pull`: ако си редактирал `config/config.yaml` на сървъра
(а филтрираните адреси се пипат точно там), pull-ът ще спре заради конфликт.
Или редактирай конфига само на едно място и го комитвай, или преди pull:

```bash
git stash && git pull && git stash pop
```

### Проверка, че всичко е наред

```bash
./.venv/bin/shopbot status            # брояч на обяви, последни събития
./.venv/bin/shopbot listings          # активните обяви
ls -la data/                          # база, снимки, екранни снимки при грешка
```

## Когато нещо се счупи

Почти винаги е едно от двете:

**„Не намирам X на страницата"** — сайтът е сменил дизайна си.
Пусни `shopbot calibrate <site>`, погледни JSON-а и добави новия селектор
най-отгоре в списъка в `config/selectors.yaml`. Код не се пипа.

**„нужен е ръчен вход"** — сесията е изтекла.
`shopbot login <site>` и толкова.

Диагностика:

```bash
journalctl -u shopbot -n 200 --no-pager
shopbot status
ls data/publish_fail_*.png       # екранни снимки от неуспешни публикации
```
